12.EVLVS-admin-user-creation.md
This document details the update to the user registration API (/api/register) to support role-based user creation.

Previously, user registration defaulted to applicant or accepted unvalidated roles. The registration endpoint has been updated so that:   
JS

Public / Unauthenticated Users: Always get assigned the applicant role, regardless of any role field sent in the request body.

Admin Users: When authenticated with an active admin JWT token, admins can specify and create users with any valid role (doc_reviewer, visa_staff, manager, admin, or applicant).

Step 1: Add Optional Token Verification Middleware
To allow the registration endpoint to handle both public sign-ups (no token) and admin-driven user creation (with JWT token), an optionalVerifyToken middleware was added to middleware/authenticationManager.js.   
JS

If an Authorization header is present and valid, req.user is populated. If no token is provided or the token is unauthenticated, the request proceeds without throwing a 401/403 error.   
JS

middleware/authenticationManager.js Update
JavaScript
// middleware/authenticationManager.js
const jwt = require('jsonwebtoken');

const JWT_SECRET = process.env.JWT_SECRET || 'your_super_secret_key_123';

// Strict token verification (for protected routes)
exports.verifyToken = (req, res, next) => {
  const authHeader = req.headers['authorization'];
  const token = authHeader && authHeader.split(' ')[1];

  if (!token) {
    return res.status(401).json({ message: 'Access denied. No token provided.' });
  }

  try {
    const decoded = jwt.verify(token, JWT_SECRET);
    req.user = decoded;
    next();
  } catch (err) {
    return res.status(403).json({ message: 'Invalid or expired token.' });
  }
};

// Soft / Optional token verification (populates req.user if token is present and valid)
exports.optionalVerifyToken = (req, res, next) => {
  const authHeader = req.headers['authorization'];
  const token = authHeader && authHeader.split(' ')[1];

  if (token) {
    try {
      const decoded = jwt.verify(token, JWT_SECRET);
      req.user = decoded; // Populates req.user if valid JWT is present
    } catch (err) {
      // Proceed as unauthenticated request if token is invalid or expired
    }
  }
  next();
};
Step 2: Update Registration Controller Logic
The registerUser function in controllers/newRegistrationManager.js now checks req.user?.role.   
JS

If req.user is present and req.user.role === 'admin', the controller validates and assigns the specified role field from req.body.

Otherwise, the assigned role is restricted strictly to applicant.

Step 4: Test Role-Based Registration with curl
1. Public User Attempting Privilege Escalation
When an unauthenticated user submits role: "admin" during public registration, the system ignores the parameter and assigns role: "applicant".

Bash
curl -X POST http://localhost:5000/api/register \
  -H "Content-Type: application/json" \
  -d '{
    "first_name": "John",
    "last_name": "Public",
    "email": "john.public@example.com",
    "password": "Password123!",
    "role": "admin"
  }'

2. Admin Creating a visa_staff User
Log in as an admin user to acquire an admin JWT:

Bash
curl -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "admin@example.com", "password": "adminpassword"}'
Export the resulting admin token:

Bash
ADMIN_TOKEN="YOUR_ADMIN_JWT_HERE"
