# Admin User Management Frontend Implementation Guide

## Admin User Management System Architecture

This document explains the design and implementation of the Admin User Management frontend portal (`admin.html`). To support administrative capabilities—such as provisioning internal staff accounts, updating user roles, toggling account statuses, and deleting users—a dedicated administrative portal was built matching the existing design system (`stylesheet.css`) used across the applicant and reviewer portals.

All administrative UI workflows consume the backend API endpoints exposed under `/api/admin/users` and enforce client-side role guards alongside server-side Bearer token authorization:

- **Client-Side Authorization Guard:** On page initialization, `admin.html` parses the stored JWT token and user profile from `localStorage`. Non-admin users or unauthenticated sessions are immediately redirected to `login.html`.
- **API Middleware Guard:** Every outgoing HTTP request appends the Bearer JWT token in the `Authorization` header (`Bearer <token>`), ensuring backend protection via `verifyToken` and `verifyRole(['admin'])`.

## Key Capabilities & UI Features

The frontend portal provides 5 core administrative workflows:

- **User Roster Display (`GET /api/admin/users`):** Displays all registered users with real-time status badges, role indicators, and formatted creation timestamps.
- **Dynamic View Filtering:** Allows admins to filter the user list instantly across **All Users**, **Active Users**, and **Inactive Users** with live counter updates.
- **Create New User Modal (`POST /api/admin/users`):** Modal dialog with full form validation for provisioning new accounts with assigned roles (`applicant`, `doc_reviewer`, `visa_staff`, `manager`, `admin`).
- **Account Status & Role Lifecycle Management (`PATCH /api/admin/users/:id/deactivate|activate` & `PUT /api/admin/users/:id/:role`):** Interactive modal on user selection allowing administrators to toggle account status and update user roles.
- **User Account Deletion (`DELETE /api/admin/users/:id`):** Hard deletion flow with explicit browser confirmation prompts.

---

## 1. Architectural Strategy

Instead of embedding administrative controls within generic portal pages, we established a standalone administrative client module (`admin.html`).

### Key Benefits:

- **UI Isolation & Role Integrity:** Secures administrative controls behind clear role-based UI separation, keeping applicant and reviewer views focused and isolated.
- **Modal-Driven Administrative Workflows:** Employs HTML5 `<dialog>` elements for provisioning and managing accounts without triggering full page reloads.
- **Design Token & Component Reuse:** Inherits styles directly from `stylesheet.css` (topbar, `.btn-primary`, `.app-card`, form groups, dropdown menus) to ensure a unified user experience.
- **Reactive DOM Rendering:** Dynamically transforms JSON responses from backend APIs into formatted user cards with instant feedback on administrative operations.

### B. Routing & Redirection: `login.html`

Integrated explicit redirection to `/admin.html` when an authenticating user possesses the `admin` role.

```javascript
// Excerpt from login.html response handler
const userRole = data.user.role; 

setTimeout(() => {
  switch (userRole) {
    case 'admin':
      window.location.href = '/admin.html';
      break;
    case 'doc_reviewer':
    case 'visa_staff':
    case 'manager':
      window.location.href = '/reviewer.html';
      break;
    case 'applicant':
    default:
      window.location.href = '/applicant.html';
      break;
  }
}, 1000);
```

## 3. UI & API Integration Matrix

| UI Trigger | User Action | Target API Endpoint | HTTP Method | Request Payload / Headers | UI Outcome |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Page Initialization** | Navigating to `/admin.html` | `/api/admin/users` | `GET` | `Authorization: Bearer <token>` | Populates user list and tab counts |
| **Tab Navigation** | Clicking *All*, *Active*, or *Inactive* tabs | Client-side filter | N/A | Filtering on `is_active` flag | Re-renders user cards instantly |
| **Create User Button** | Clicking `+ Create new user` | Opens `<dialog id="newUserModal">` | N/A | N/A | Displays creation form modal |
| **Submit New User** | Submitting creation form | `/api/admin/users` | `POST` | `{ first_name, last_name, email, role, password }` | Adds user, reloads roster, closes modal |
| **User Card Click** | Clicking any user row card | Opens `<dialog id="userActionModal">` | N/A | Passes `user_id` to modal state | Displays management actions for user |
| **Update Role Button** | Clicking `Update` in action modal | `/api/admin/users/:id/:role` | `PUT` | `Authorization: Bearer <token>` | Updates role, reloads roster |
| **Deactivate / Activate** | Clicking status toggle button | `/api/admin/users/:id/deactivate` or `/activate` | `PATCH` | `Authorization: Bearer <token>` | Toggles state, updates roster |
| **Delete User Button** | Clicking `Delete User Account` | `/api/admin/users/:id` | `DELETE` | `Authorization: Bearer <token>` | Confirmation prompt, deletes record |

# Admin User UI Verification Workflow

This section outlines manual browser verification steps for administrative user management operations.

---

## 1. Authentication & Role-Based Access Gate

1. Log in via `login.html` using administrative credentials (`admin@example.com`).
2. Verify automatic redirection to `/admin.html`.
3. Verify that the navigation header displays administrator details and initials in the top right profile dropdown.

---

## 2. User Provisioning

1. Click the **`+ Create new user`** button in the topbar.
2. Fill out the dialog form fields:
   - **First Name:** `Test`
   - **Last Name:** `Reviewer`
   - **Email:** `test.reviewer@example.com`
   - **Role:** `doc_reviewer`
   - **Password:** `Password123`
3. Click **Create Account**.
4. Confirm success message appearance and verify that `Test Reviewer` appears at the top of the user roster.

---

## 3. Account Status & Role Updates

1. Click on the newly created `Test Reviewer` user card to open the action modal.
2. Select `manager` from the **Change Role** dropdown and click **Update**.
3. Confirm the role badge updates to `manager`.
4. Re-open the modal and click **Deactivate User**.
5. Verify the user status badge updates to red `Deactivated` and the **Inactive** filter counter increments.

---

## 4. Account Deletion

1. Open the action modal for a deactivated user.
2. Click **Delete User Account**.
3. Confirm the native browser confirmation prompt (`OK`).
4. Verify the user record is removed from the user list and total user counts are updated across tabs.
