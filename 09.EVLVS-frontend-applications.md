# EVLVS Frontend — New Application Modal + Fetch Create/List

Wires up `applicant.html`'s "+ New application" button to an actual popup form, POSTs it to `POST /api/applications` as `FormData` (per the backend doc), and fetches `GET /api/applications` to fill in the Active/History tabs. An application counts as **history** once `status` is `approved` or `rejected`; everything else (`Draft` and anything in between) is **active**.

Kept intentionally small: the popup uses the native HTML `<dialog>` element, which gets you a centered overlay, a dimmed backdrop, and Escape-to-close for free — no custom modal CSS/JS needed for the open/close mechanics themselves.

`first_name`/`last_name` are pulled straight from the cached `user` object in `localStorage` (already parsed earlier in the script) rather than shown as editable fields in the form — the backend rejects the request with a 403 if they don't exactly match the logged-in profile, so there's no reason to let them be edited here.

## Step 3: Add the Modal Wiring + Fetch/Render Logic

Append this at the very end of the `<script>` block, right after the existing "Logout Handler":

```js
    // 4. New Application Modal
    const newAppBtn = document.getElementById('newAppBtn');
    const newAppModal = document.getElementById('newAppModal');
    const newAppForm = document.getElementById('newAppForm');
    const newAppMsg = document.getElementById('newAppMsg');
    const cancelAppBtn = document.getElementById('cancelAppBtn');

    newAppBtn.addEventListener('click', () => {
      newAppForm.reset();
      newAppMsg.textContent = '';
      newAppModal.showModal();
    });

    cancelAppBtn.addEventListener('click', () => {
      newAppModal.close();
    });

    newAppForm.addEventListener('submit', async (e) => {
      e.preventDefault();
      newAppMsg.style.color = 'black';
      newAppMsg.textContent = 'Submitting...';

      const user = JSON.parse(localStorage.getItem('user'));
      const formData = new FormData();
      formData.append('first_name', user.first_name);
      formData.append('last_name', user.last_name);
      formData.append('visa_type', document.getElementById('visaType').value);
      formData.append('passport_number', document.getElementById('passportNumber').value);
      formData.append('photo', document.getElementById('photoInput').files[0]);
      formData.append('passport', document.getElementById('passportInput').files[0]);

      try {
        const response = await fetch('/api/applications', {
          method: 'POST',
          headers: { 'Authorization': `Bearer ${token}` },
          body: formData
        });
        const data = await response.json();

        if (response.ok) {
          newAppMsg.style.color = 'green';
          newAppMsg.textContent = 'Application submitted!';
          loadApplications();
          setTimeout(() => newAppModal.close(), 800);
        } else {
          newAppMsg.style.color = 'red';
          newAppMsg.textContent = data.error || 'Failed to submit application.';
        }
      } catch (err) {
        console.error('Application submit error:', err);
        newAppMsg.style.color = 'red';
        newAppMsg.textContent = 'Unable to connect to server.';
      }
    });

    // 5. Fetch & Render Applications (Active vs. History)
    async function loadApplications() {
      try {
        const response = await fetch('/api/applications', {
          headers: { 'Authorization': `Bearer ${token}` }
        });
        const data = await response.json();
        if (!response.ok) return;

        const active = data.applications.filter(a => a.status !== 'approved' && a.status !== 'rejected');
        const history = data.applications.filter(a => a.status === 'approved' || a.status === 'rejected');

        renderApplications('active-section', active, 'No active applications found. Click "+ New application" to start.');
        renderApplications('history-section', history, 'You have no past applications.');
      } catch (err) {
        console.error('Failed to load applications:', err);
      }
    }

    function renderApplications(sectionId, list, emptyMessage) {
      const section = document.getElementById(sectionId);
      if (list.length === 0) {
        section.innerHTML = `<p style="color: #5f6368;">${emptyMessage}</p>`;
        return;
      }
      section.innerHTML = list.map(app => `
        <div class="app-card">
          <div><strong>${app.visa_type}</strong> — ${app.passport_number}</div>
          <div class="app-status">${app.status}</div>
        </div>
      `).join('');
    }
```

`loadApplications` and `renderApplications` are function declarations, so they're hoisted — calling `loadApplications()` earlier in the script (Step 2) before its definition appears later in the file works fine.

## Notes on What Was Kept Simple

- **Application data is inserted via `innerHTML` without escaping.** Normally worth avoiding, but `GET /api/applications` only ever returns the logged-in user's own records — so at worst a user could inject something into their own view (self-XSS), not another user's. Worth revisiting if this list ever shows data belonging to other people (e.g. a reviewer/admin view).
- **No client-side file-type/size checks beyond the `accept=""` hints** on the file inputs — matches the backend review notes already flagged (server-side file-size limits and MIME validation aren't in place yet either).
- **The `<dialog>` element** needs a reasonably modern browser — supported in all current major browsers, just worth knowing if you ever need to support something very old.
